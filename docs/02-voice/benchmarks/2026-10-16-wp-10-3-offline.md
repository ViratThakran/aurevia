# WP-10.3 offline numbers (2026-10-16)

**Offline only.** No model was called. These numbers come from the real prompt builder and
tool definitions and from scripted fake-model turns in the test suite. They say nothing about
latency. The latency effect must be measured with a model key (`scripts/voice_benchmark.py`,
which now also reports `cached_input_tokens_per_turn`).

Sample agent: full setup, 6 earlier-call notes, 6 free meeting times, stage `next_step`.
Token figures are estimates at about 4 characters per token.

## Size of one spoken-path model request

| | before (`main` 196f112) | after (this branch) |
|---|---|---|
| System prompt | 4,136 chars (~1,030 tokens) | 4,778 chars (~1,190 tokens; includes 6 listed meeting times) |
| Speech-path tool definitions | 3,284 chars (~820 tokens) | 3,379 chars (~845 tokens) |
| Marked cacheable (tools + stable prompt) | 0 | 7,418 chars (~1,850 tokens, about 91%) |
| Sent fresh every request | ~1,850 tokens + history | ~185 tokens + history (once the cache is warm) |

## Model requests before the first word (scripted fake model)

| Turn | before | after |
|---|---|---|
| Prospect asks when we could talk (stage pitch/next step) | 2 (slots tool, then speak) | 1 (times already in the prompt) |
| Prospect accepts a time that was offered | 2 (book, then speak) | 2 (book, then speak) |
| Prospect names a time in one go ("book Tuesday at 11") | 3 (slots, book, speak) | 2 (book, then speak) |

The booking still goes through `book_meeting`, which re-checks the slot, runs in a savepoint,
writes an audit row and is idempotent. The pre-lookup itself runs through the same executor
and writes an audit row.

Covered by tests: `test_free_times_are_prefetched_through_the_audited_tool_when_a_meeting_is_near`,
`test_listed_time_books_in_one_tool_round_and_is_still_checked`,
`test_engine_marks_the_stable_prompt_part_as_cacheable`,
`test_cached_input_tokens_are_recorded_per_request`.
