# WP-10.3 offline numbers (2026-10-16)

**Offline only.** No model was called. These numbers come from the real prompt builder and
tool definitions and from scripted fake-model turns in the test suite. They say nothing about
latency. The latency effect must be measured with a model key (`scripts/voice_benchmark.py`,
which now also reports `cached_input_tokens_per_turn`).

Sample agent: full setup, 6 earlier-call notes, 6 free meeting times (next step only).
Token figures are estimates at about 4 characters per token.

## Size of one spoken-path model request (re-run 2026-10-17)

| Stage | | before (`main` 196f112) | after (this branch) |
|---|---|---|---|
| pitch | system prompt + speech tools | 7,437 chars (~1,860 tokens) | 7,572 chars (~1,890 tokens) |
| pitch | sent fresh each request (warm cache) | ~1,860 tokens + history | ~40 tokens + history |
| next step | system prompt + speech tools | 7,420 chars (~1,855 tokens) | 8,157 chars (~2,040 tokens, includes 6 listed times) |
| next step | sent fresh each request (warm cache) | ~1,855 tokens + history | ~185 tokens + history |

"Sent fresh" is everything after the cacheable prefix (tools + the stable part of the prompt,
7,418 chars, about 1,850 tokens). Before this branch nothing was marked cacheable.

## Model requests before the first word (scripted fake model)

| Turn | before | after |
|---|---|---|
| Pitch stage: prospect asks when we could talk | 2 (slots tool, then speak) | 2 (unchanged: no lookup at pitch) |
| Next-step stage: prospect asks when we could talk | 2 (slots tool, then speak) | 1 (times already in the prompt) |
| Next-step stage: prospect accepts an offered time | 2 (book, then speak) | 2 (book, then speak) |
| Next-step stage: prospect names a time in one go | 3 (slots, book, speak) | 2 (book, then speak) |

Listed times are at most 5 minutes old: a new 5-minute window is a new lookup request (its own
audit row); within a window the same lookup is answered from its audit row (idempotency,
unchanged).

The booking still goes through `book_meeting`, which re-checks the slot, runs in a savepoint,
writes an audit row and is idempotent. The pre-lookup itself runs through the same executor
and writes an audit row.

Covered by tests: `test_free_times_are_prefetched_only_at_the_next_step_stage`,
`test_listed_times_are_refreshed_in_a_new_window_and_reused_within_one`,
`test_listed_time_books_in_one_tool_round_and_is_still_checked`,
`test_engine_marks_the_stable_prompt_part_as_cacheable`,
`test_cached_input_tokens_are_recorded_per_request`.
